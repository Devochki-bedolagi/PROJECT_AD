## 3. SUPABASE — ЧТО ЭТО И КАК РАБОТАЕТ

### Определение:
**Supabase** — это облачная платформа, которая предоставляет:
- Готовую базу данных PostgreSQL
- Автоматический REST API к базе данных
- Аутентификацию пользователей
- Хранилище файлов

### Почему Supabase, а не свой сервер:
| Преимущество | Объяснение |
|--------------|------------|
| ✅ Быстро | Не нужно писать серверный код |
| ✅ Бесплатно | Есть бесплатный тариф |
| ✅ Надёжно | PostgreSQL — профессиональная БД |
| ✅ Безопасно | Встроенная авторизация и RLS |

### Как подключается Supabase:

#### Шаг 1: Подключение библиотеки (в index.html)
```html
<script src="https://cdn.jsdelivr.net/npm/@supabase/supabase-js@2"></script>
```
**Что делает:** Загружает JavaScript-клиент Supabase через CDN (сеть доставки контента)

#### Шаг 2: Инициализация клиента (в script.js)
```javascript
const SUPABASE_URL = 'https://zfxujjrfphkgqpilnrec.supabase.co';
const SUPABASE_ANON_KEY = 'eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...';

const supabaseClient = window.supabase.createClient(SUPABASE_URL, SUPABASE_ANON_KEY);
```

### Что означают параметры:

| Параметр | Значение | Зачем нужно |
|----------|----------|-------------|
| `SUPABASE_URL` | `https://zfxujjrfphkgqpilnrec.supabase.co` | Адрес вашего проекта Supabase в облаке |
| `SUPABASE_ANON_KEY` | Длинная строка (JWT-токен) | Публичный ключ для доступа из браузера |

### ⚠️ Важно про ANON_KEY:
- Это **НЕ секретный ключ**, его можно хранить в коде
- Он даёт ограниченный доступ (только чтение/запись в разрешённые таблицы)
- Настоящий секретный ключ (`service_role key`) нельзя показывать в коде

## 4. СТРУКТУРА БАЗЫ ДАННЫХ

### Таблица: `feedback_messages`

Создаётся файлом миграции: `database/migrations/001_create_feedback_messages.sql`

### SQL-код миграции:
```sql
CREATE TABLE IF NOT EXISTS feedback_messages (
  id UUID DEFAULT gen_random_uuid() PRIMARY KEY,
  created_at TIMESTAMPTZ DEFAULT NOW(),
  name TEXT NOT NULL,
  email TEXT NOT NULL,
  message TEXT NOT NULL,
  consent_given BOOLEAN NOT NULL DEFAULT false,
  status TEXT DEFAULT 'new' CHECK (status IN ('new', 'read', 'replied'))
);

CREATE INDEX IF NOT EXISTS idx_feedback_created_at 
  ON feedback_messages(created_at DESC);
```

### Подробное описание каждого поля:

| Поле | Тип данных | Описание | Заполняется |
|------|------------|----------|-------------|
| **id** | UUID | Уникальный идентификатор сообщения | Автоматически (gen_random_uuid()) |
| **created_at** | TIMESTAMPTZ | Дата и время отправки | Автоматически (NOW()) |
| **name** | TEXT | Имя отправителя | Пользователь (обязательно) |
| **email** | TEXT | Email отправителя | Пользователь (обязательно) |
| **message** | TEXT | Текст сообщения | Пользователь (обязательно) |
| **consent_given** | BOOLEAN | Согласие на обработку данных | Всегда `true` при отправке |
| **status** | TEXT | Статус обработки | `'new'` при создании |

### Ограничения (CONSTRAINTS):

1. **PRIMARY KEY** — поле `id` уникально для каждой записи
2. **NOT NULL** — поля `name`, `email`, `message`, `consent_given` обязательны
3. **CHECK** — поле `status` может быть только: `'new'`, `'read'`, или `'replied'`
4. **DEFAULT** — значения по умолчанию:
   - `id` → новый UUID
   - `created_at` → текущее время
   - `consent_given` → `false`
   - `status` → `'new'`

### Индекс:
```sql
CREATE INDEX idx_feedback_created_at ON feedback_messages(created_at DESC);
```
**Зачем:** Ускоряет сортировку сообщений по дате (чтобы новые были сверху)

## 7. ВОПРОСЫ ДЛЯ ЗАУЧИВАНИЯ

### ❓ Вопрос 1: Что такое бэкенд в вашем проекте?

**Ответ:**
> В моём проекте бэкенд реализован через облачный сервис Supabase. Это BaaS-платформа (Backend as a Service), которая предоставляет готовую базу данных PostgreSQL и REST API к ней. Серверный код писать не нужно — вся логика работает на клиенте через JavaScript-библиотеку @supabase/supabase-js.

---

### ❓ Вопрос 2: Какую функциональность бэкенда вы реализовали?

**Ответ:**
> Я реализовала форму обратной связи. Когда пользователь заполняет форму (имя, email, сообщение) и нажимает "Отправить", данные валидируются на клиенте и сохраняются в базу данных Supabase в таблицу `feedback_messages`. Каждое сообщение получает статус 'new' и временную метку.

---

### ❓ Вопрос 3: Как устроена база данных?

**Ответ:**
> В базе данных PostgreSQL создана таблица `feedback_messages` со следующими полями:
> - `id` (UUID, первичный ключ, автогенерация)
> - `created_at` (TIMESTAMPTZ, дата/время, авто)
> - `name` (TEXT, обязательно)
> - `email` (TEXT, обязательно)
> - `message` (TEXT, обязательно)
> - `consent_given` (BOOLEAN, по умолчанию false)
> - `status` (TEXT, может быть 'new', 'read' или 'replied', по умолчанию 'new')
>
> Также создан индекс `idx_feedback_created_at` для быстрой сортировки по дате.

---

### ❓ Вопрос 4: Как происходит отправка данных в Supabase?

**Ответ:**
> 1. Пользователь заполняет форму и нажимает "Отправить"
> 2. Событие `submit` перехватывается через `addEventListener`
> 3. `preventDefault()` отменяет стандартную отправку формы
> 4. Данные собираются через `querySelector` и `value.trim()`
> 5. Проверяется чекбокс согласия и заполненность полей
> 6. Через `supabaseClient.from('feedback_messages').insert({...})` данные отправляются в БД
> 7. При успехе — форма очищается, пользователю показывается уведомление
> 8. При ошибке — выводится сообщение об ошибке

---

### ❓ Вопрос 5: Что такое `await` и зачем он нужен?

**Ответ:**
> `await` — это оператор для работы с асинхронными операциями. Он "ждёт" завершения Promise (обещания), прежде чем продолжить выполнение кода. В моём проекте `await` используется при отправке данных в Supabase, потому что сетевой запрос выполняется не мгновенно. Без `await` код продолжил бы выполняться до получения ответа от сервера.

---

### ❓ Вопрос 6: Что такое деструктуризация в строке `const { data, error } = ...`?

**Ответ:**
> Деструктуризация — это синтаксический сахар JavaScript для извлечения значений из объектов. Запись `const { data, error } = response` равносильна `const data = response.data; const error = response.error;`. В моём случае Supabase возвращает объект с полями `data` (результат операции) и `error` (ошибка, если была).

---

### ❓ Вопрос 7: Зачем нужен блок `try...catch`?

**Ответ:**
> Блок `try...catch` используется для обработки ошибок. Код в блоке `try` может вызвать исключение (например, ошибка сети или проблемы с сервером). Если ошибка происходит, выполнение переходит в блок `catch`, где можно корректно обработать ошибку — вывести сообщение пользователю и записать ошибку в консоль для отладки.

---

### ❓ Вопрос 8: Что такое UUID и почему он используется для первичного ключа?

**Ответ:**
> UUID (Universally Unique Identifier) — это 128-битный уникальный идентификатор. Формат: `xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx`. В отличие от автоинкремента (1, 2, 3...), UUID генерируется случайно и гарантирует уникальность даже в распределённых системах. В Supabase UUID используется по умолчанию для первичного ключа, что повышает безопасность (нельзя угадать ID следующей записи).

---

### ❓ Вопрос 9: Что такое RLS (Row Level Security)?

**Ответ:**
> RLS (Row Level Security) — это механизм безопасности PostgreSQL, который ограничивает доступ к строкам таблицы на основе политик. В Supabase RLS должен быть включён для таблиц, чтобы клиенты с anon-ключом могли выполнять только разрешённые операции. Например, можно разрешить всем вставлять новые записи, но читать только свои.

---

### ❓ Вопрос 10: Какие ещё методы Supabase можно использовать?

**Ответ:**
> Кроме `.insert()`, Supabase поддерживает:
> - `.select()` — получение данных (SELECT)
> - `.update()` — обновление записей (UPDATE)
> - `.delete()` — удаление записей (DELETE)
> - `.eq('field', value)` — фильтрация по полю (WHERE)
> - `.order('field', { ascending: false })` — сортировка (ORDER BY)
> - `.limit(n)` — ограничение количества записей (LIMIT)
>
> Пример: получить все новые сообщения:
> ```javascript
> const { data, error } = await supabaseClient
>   .from('feedback_messages')
>   .select('*')
>   .eq('status', 'new')
>   .order('created_at', { ascending: false });
> ```

| **Supabase** | Облачный бэкенд (BaaS) на основе PostgreSQL |
| **PostgreSQL** | Реляционная база данных |
| **REST API** | Способ общения клиента с сервером через HTTP-запросы |
| **UUID** | Уникальный идентификатор (128 бит) |
| **Promise** | Объект, представляющий результат асинхронной операции |
| **async/await** | Синтаксис для работы с Promise |
| **Деструктуризация** | Извлечение значений из объекта в переменные |
| **Валидация** | Проверка данных на корректность |
| **RLS** | Безопасность на уровне строк в PostgreSQL |

### 📝 Код для запоминания:

#### Инициализация клиента:
```javascript
const supabaseClient = window.supabase.createClient(SUPABASE_URL, SUPABASE_ANON_KEY);
```

#### Вставка в базу:
```javascript
const { data, error } = await supabaseClient
  .from('feedback_messages')
  .insert({ name, email, message, consent_given: true, status: 'new' });
```

#### Обработка ошибки:
```javascript
try {
  // код
} catch (err) {
  console.error('Ошибка:', err);
  alert('Произошла ошибка');
}
```
